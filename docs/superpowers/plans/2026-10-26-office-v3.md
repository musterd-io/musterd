# Office v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, in your own seat, one lane per increment. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The `/live` office seats 28 on an asymmetric floor of planks and café tile, with chairs, plants and a café corner that read as real, and members who walk on the ground, sit with hands down and carry their laptop.

**Architecture:** Room and figure are pre-rendered Blender sprites (`packages/web/art/office/scene.py`, `figure.py` → `render.py` → `src/live/office-scene/rendered/assets/`) composed at runtime by `render.ts`; placement, navigation and seating are data in `layout.ts` consumed by `nav.ts`, `seating.ts` and `actors.ts`. Every increment changes the data or the model, re-renders only what the per-call store misses, and lands as one PR under its lane.

**Tech Stack:** Blender 5.2 (Python), TypeScript, Vitest, `render_watch.py`.

**Spec:** `docs/superpowers/specs/2026-10-26-office-v3-design.md`

## Global Constraints

- Every desk seat keeps 60 walkable units behind it and is reachable from `ENTRANCE` (`nav.test.ts:34`); every pair of `LEISURE_SPOTS` ≥ `MIN_SPOT_GAP` 46 on screen; `COFFEE_STAND`, `FRIDGE_STAND`, `COOLER_STAND`, `SINK_STAND` walkable.
- `officeArtBytes` ≤ 8,420,000 (`docs/perf/budgets.json`); a raise is logged in `docs/perf/web-live-baseline.md` in the same PR.
- No local full-suite runs; run only the test file you touch. Renders run in the background via `render_watch.py` with the store (resume by re-running the same command).
- Each increment: branch from `origin/main`, PR body line `` Lane `<id>`. ``, `gh pr merge --squash --auto --delete-branch`, `lane_submit`, then detach and `git branch -D`.
- A tee change is a full figure render (~5.5 h). Tasks 7 and 8 touch clips only, never `TOPS`.
- `scene.py` mirrors `layout.ts` constants by hand (`PODS`, `NOOK`, `LOUNGE`, `MEETING`, …): every layout change edits both, and `layout.test.ts` is the only guard, so add the mirror check where a task introduces a new constant.
