# Scenario 4 — Cold start on a clean machine (dry run)

- Tester: ryder (agent seat), with nick for the two harness sign-ins
- Date: 2026-10-20
- Build: published `@musterd/cli` 0.5.0 first, then main `cd3a0ee1` packed as the 0.6.0
  candidate, then that candidate plus the init fix (PR #3084)
- Setup: a new Fly machine (`debian:bookworm`, sjc, 2 GB). A `dev` user with curl, git and sudo,
  no Node, and an empty `git init` folder at `~/your-project`. The site was read from another
  machine and its commands typed as written. The init prompts were answered with Enter
  throughout, a stranger's first choice. Harnesses: Claude Code 2.1.305 and Codex 0.163.0, each
  signed in once by nick.
- Result: blocked at `musterd init` on 0.5.0 and on main. Completed with the fix.

This is the dry run nick asked for, two days before the gate. The gate run repeats it against
main on 2026-10-22.

## What broke

1. **Every first `musterd init` on a new team connects nothing.** With every default accepted
   (start the daemon, name the team, connect the agents you already have), it ends:
   `✗ your-project — invalid service token for team "dogfood"` and `0 seats`. This happens on
   0.5.0 and on main alike. `createTeam` handed the creator's v0.2 `mskd_` seat token to every
   later call, and the daemon accepts that prefix only from service seats. This is the moment a
   stranger would have had to ask someone, about 18 minutes in, most of it waiting on sign-ins.
   Fixed in PR #3084 (lane `01M5DZXCN6`). With the fix, the same keystrokes end with
   `✓ your-project — Claude Code, Codex`.
2. **The tour dies in a new project.** Init's next offer, "Take the 5-minute tour?", defaults to
   Yes. It then runs `git worktree add` from `HEAD` in a folder with no commits and no
   `origin`: `fatal: not a valid object name: 'HEAD'`. Lane `01M5E08TQ7`.
3. **The record names the wrong model.** Claude Code and Codex share the one connected seat. Codex's
   first act is stamped `model: claude-opus-5-5, model_source: observed`, and Claude's own act
   carries no model at all. The homepage claims the record names "which model is doing it".
   Lane `01M5E085SA`.

## What surprised you

- **Enter on the team name was refused.** The prompt shows `dawn`, but clack validates the empty
  input before it applies the default, so Enter gets "use lowercase letters…". Fixed in #3084.
- **The name prompt suggested `nick`.** That was a hardcoded placeholder on a stranger's machine.
  Enter took `dev`, the login. Fixed in #3084.
- **Inside your own project, `musterd status` says `you are your-project`** (the agent) and lists
  the person as `OUT`. "One seat per repo" makes the person's repo the agent's seat, so the CLI
  there acts as the agent. That is correct by the binding rule, but nothing on the site prepares
  you for it.
- **Codex has no musterd tools until you trust the folder.** Init writes the server into the
  project's `.codex/config.toml`, and Codex reads that only for a trusted project. Interactive
  `codex` asks on first launch; `codex exec` silently runs without the tools, and its agent fell
  back to the shell. After recording the trust that prompt writes, Codex joined at once.
- `npm install -g @musterd/cli` printed four deprecation warnings (prebuild-install and three
  OpenTelemetry packages) on a first install.
- `musterd init --help` prints the whole command map instead of init's own help.
  `musterd help init` is the form that works.

## What you had to already know

- **How to get Node 22.** The site says "You need Node 22 or later" and stops there. I used nvm
  because I knew to. A visitor without Node has no next step on the page.
- **That a brand-new folder needs a first commit before the tour.** I knew because I read the
  error. A stranger reads `fatal: not a valid object name: 'HEAD'` and stops.
- **That Codex needs the folder trusted.** Nothing in init or on the site says so.
- **That `invalid service token` was not my fault.** I read the source. A stranger has no way to
  recover from it short of asking us.

## Verdict on the claim

false on today's main, holds with #3084 — "Runs on your machine, no account" fails at the first
real step for anyone who creates a team. With the fix, both harnesses were online and had sent an
act within a minute of starting.
